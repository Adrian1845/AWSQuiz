## Explanation

Correct option:

Create an AWS Cost Anomaly Detection monitor and configure an alert subscription to notify designated stakeholders when the monitor detects anomalous spending

AWS Cost Anomaly Detection is specifically designed to identify unusual AWS spending patterns. The service uses machine learning models to evaluate historical spending behavior and identify anomalous costs while accounting for factors such as normal growth and recurring spending patterns. This capability directly addresses the requirement to detect spending that deviates unexpectedly from normal usage.

A cost monitor defines the AWS spending that Cost Anomaly Detection evaluates. The company can create an alert subscription for the monitor and specify the stakeholders who should receive notifications. AWS supports email notifications for daily or weekly summaries and Amazon SNS for individual alerts, allowing responsible teams to learn about significant anomalies soon after AWS identifies them.

Unlike a fixed budget or billing alarm, Cost Anomaly Detection does not require the company to predict the exact monetary value at which unusual spending will occur. AWS determines whether spending behavior is anomalous based on learned cost patterns, and the company can configure notification thresholds based on the financial impact or percentage impact of an anomaly. Therefore, Cost Anomaly Detection provides the most appropriate combination of continuous anomaly identification and stakeholder notification.

Incorrect options:

Use AWS Pricing Calculator to model the expected cost of the existing EC2 workload and periodically compare the estimate with actual AWS charges - AWS Pricing Calculator allows architects to estimate the expected cost of AWS architectures before or during deployment. The company could model its EC2 configuration and compare the estimate with actual spending to gain a general understanding of whether its costs align with expectations.

However, AWS Pricing Calculator does not continuously monitor actual account spending or automatically detect anomalous cost patterns. It also does not generate alerts when AWS identifies unexpected changes in real consumption, so this approach would require ongoing manual comparison and would not satisfy the monitoring and notification requirements.

Enable Amazon CloudWatch billing metrics, create alarms for predetermined estimated charge thresholds, and configure Amazon SNS notifications for the finance team - Amazon CloudWatch can receive AWS billing metrics such as estimated charges, and the company can create alarms that publish notifications through Amazon SNS when those charges exceed specified thresholds. This configuration can help an organization track whether total estimated spending crosses a known monetary limit.

The issue with this approach is that CloudWatch billing alarms use static thresholds rather than anomaly detection based on historical spending behavior. A cost increase could be unusual for the company's normal usage pattern without crossing the configured CloudWatch threshold, while normal growth could cross the threshold without representing an anomaly. AWS Cost Anomaly Detection is purpose-built for the requirement.

Create a zero spend budget from an AWS Budgets template and configure the budget to notify stakeholders when spending exceeds the configured threshold - AWS Budgets provides templates that simplify creating budgets and associated notifications. A zero spend budget specifically alerts an organization when spending exceeds AWS Free Tier limits, making it useful for accounts in which the organization expects no billable usage.

This company already operates production workloads on Amazon EC2 and therefore expects ongoing AWS charges. A zero spend budget does not distinguish expected spending from anomalous spending and would generate alerts simply because costs exist. It does not satisfy the requirement to identify spending that deviates unexpectedly from established patterns.
