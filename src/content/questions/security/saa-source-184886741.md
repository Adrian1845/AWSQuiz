## Explanation

Correct option:

Create a Route 53 Resolver outbound endpoint. Define a forwarding rule that routes DNS queries for on-premises domains to the on-premises DNS server. Associate the rule with the VPC

This solution allows DNS queries from AWS-based workloads (inside the VPC) to resolve private on-premises domain names using a Route 53 Resolver outbound endpoint. The outbound endpoint forwards DNS queries from the VPC to the on-premises DNS server across the site-to-site VPN. The forwarding rules determine which domain names are sent to the on-premises DNS server. Associating the rule with the correct VPC ensures that the application can securely resolve on-premises DNS records. This method follows AWS best practices for hybrid DNS resolution.

via - https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/resolver.html

Incorrect options:

Configure a Route 53 Resolver inbound endpoint and create a DNS forwarding rule. Enable recursive DNS resolution in the VPC to access on-premises services - An inbound endpoint allows DNS queries from the on-premises network to resolve AWS-hosted private domains, not the other way around. The application's requirement is to resolve on-premises DNS names from within AWS, which requires an outbound endpoint instead. Furthermore, there is no VPC configuration called “recursive DNS resolution” in this context. This option misapplies the purpose of inbound endpoints.

Create a hybrid connectivity gateway and attach the on-premises DNS servers to Route 53 as authoritative zones for internal domains - There is no such construct as a “hybrid connectivity gateway” in AWS that allows attaching DNS servers directly to Route 53. Route 53 does not support attaching on-premises DNS servers as authoritative sources. Instead, forwarding rules and Resolver endpoints are the proper mechanisms to integrate on-premises DNS resolution with AWS. This option misrepresents available AWS DNS and networking capabilities.

Create a Route 53 private hosted zone for the on-premises domain. Associate the hosted zone with the VPC to allow the application to resolve DNS names of the on-premises services - A Route 53 private hosted zone is designed to resolve DNS names within AWS resources for domains hosted on AWS, not for external or on-premises DNS domains. Creating a private hosted zone for an on-premises domain name does not enable resolution of actual on-premises DNS records unless those records are manually duplicated in Route 53, which would introduce operational overhead and potential inconsistency. The correct approach for hybrid DNS resolution is to use Route 53 Resolver outbound endpoints with forwarding rules that point to the on-premises DNS servers.
