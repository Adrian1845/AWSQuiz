## Fallos actuales que sí conviene aprender

- **Seguir rutas y tipos de endpoint:** el [NAT Gateway para salida IPv4](../../src/content/questions/security/saa-source-147942821.md) va en la subred pública; la subred privada dirige hacia él su ruta de salida. Un [Alias en la raíz del dominio](../../src/content/questions/operations/saa-source-147942839.md) sirve donde un CNAME no es válido. Un [NLB con destino por ID de instancia](../../src/content/questions/architecture/saa-source-147942797.md) envía tráfico a la IP privada primaria. [AWS: destinos de NLB](https://docs.aws.amazon.com/elasticloadbalancing/latest/network/load-balancer-target-groups.html)
- **Identificar el servicio por el requisito decisivo:** [StackSets](../../src/content/questions/architecture/saa-source-147942791.md) despliega en varias cuentas y regiones; [SCT + DMS](../../src/content/questions/operations/saa-source-147942815.md) convierte esquema y migra datos; [DataSync](../../src/content/questions/storage/saa-source-147942873.md) transfiere a S3, EFS y FSx. En almacenamiento compartido, [FSx for ONTAP](../../src/content/questions/security/saa-source-147942867.md) soporta SMB y NFS; [FSx for Windows y File Gateway](../../src/content/questions/storage/saa-source-147942871.md) son opciones SMB, EFS es NFS. [AWS: DataSync](https://docs.aws.amazon.com/datasync/latest/userguide/setting-up.html)
- **Permisos y cifrado:** para dar permisos a una EC2 se asocia un rol mediante un [instance profile](../../src/content/questions/security/saa-source-147942853.md). Las [SCP](../../src/content/questions/security/saa-source-147942881.md) afectan al root de cuentas miembro, pero no a los *service-linked roles*. En [SSE-S3](../../src/content/questions/security/saa-source-147942877.md), S3 cifra cada objeto con una clave única; el *encryption context* de KMS no genera una clave nueva. [AWS: SCP](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html), [AWS: SSE-S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingServerSideEncryption.html), [AWS: contexto de cifrado](https://docs.aws.amazon.com/kms/latest/developerguide/encrypt_context.html)
- **Transferencias grandes:** en el caso de [vídeos de hasta 10 GB con usuarios lejanos](../../src/content/questions/storage/saa-source-147942859.md), S3 Transfer Acceleration es la mejor de las opciones para acelerar las subidas a un bucket regional y también puede acelerar las bajadas. AWS usa «latencia» aquí para la demora percibida de la transferencia completa; no conviene confundirla con el tiempo de ida y vuelta de un solo paquete. CloudFront sigue siendo útil para distribuir y cachear descargas. La referencia a 1 GB es una pauta de rendimiento, no un límite técnico de CloudFront. [AWS: patrones de subida con CloudFront y S3TA](https://aws.amazon.com/blogs/networking-and-content-delivery/using-aws-edge-to-optimize-object-uploads-to-amazon-s3/), [AWS: S3 Transfer Acceleration](https://docs.aws.amazon.com/AmazonS3/latest/userguide/optimizing-performance-design-patterns.html)

Las 11 regresiones no demuestran por sí solas que leyeras deprisa: el export solo guarda la opción elegida. Sí señalan respuestas inestables. Algunas, como [CloudFormation frente a StackSets](../../src/content/questions/architecture/saa-source-147942791.md), [origen válido de un Security Group](../../src/content/questions/security/saa-source-147942835.md) y [rol frente a instance profile](../../src/content/questions/security/saa-source-147942853.md), merecen releer el sustantivo exacto que cambia entre opciones. La [tenencia Dedicated de EC2](../../src/content/questions/architecture/saa-source-147942843.md) y los [AZ ID entre cuentas](../../src/content/questions/architecture/saa-source-147942889.md) son detalles legítimos, pero de menor prioridad que las reglas anteriores. ## Preguntas que no usaría como diagnóstico firme

- [Kinesis frente a SQS + Lambda](../../src/content/questions/integration/saa-source-147942819.md): la clave del proveedor elige Kinesis por la analítica de *streaming*, pero el enunciado también pide reintentos y poca implementación. SQS + Lambda sí ofrece reintentos. Falta un requisito que descarte esa opción. [AWS: reintentos con SQS y Lambda](https://docs.aws.amazon.com/lambda/latest/dg/services-sqs-errorhandling.html)
- [Lambda frente a App Runner](../../src/content/questions/compute/saa-source-147942847.md): App Runner también despliega Python desde GitHub, escala y gestiona compilación y despliegues. El enunciado no exige una función por evento ni latencia de arranque predecible que haga necesaria la concurrencia aprovisionada de Lambda. Ambas arquitecturas son defendibles; la justificación de la clave no elimina App Runner. [AWS: App Runner desde código](https://docs.aws.amazon.com/apprunner/latest/dg/service-source-code.html)
- [Systems Manager y parcheado](../../src/content/questions/architecture/saa-source-147942893.md): *Default Host Management Configuration* incorpora EC2 a Systems Manager, pero por sí sola no define la programación ni la política de instalación de parches. Para automatizar el parcheado se necesita una política de Patch Manager u otra configuración de parcheado. Ninguna opción describe por completo la solución pedida. [AWS: configuración de hosts](https://docs.aws.amazon.com/systems-manager/latest/userguide/fleet-manager-default-host-management-configuration.html), [AWS: política de parches](https://docs.aws.amazon.com/systems-manager/latest/userguide/patch-manager-create-a-patch-policy.html)
